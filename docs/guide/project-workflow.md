# 项目与数据流程

本指南说明如何定义 Schema、准备样例、生成数据、人工审核，并冻结成可训练的数据集。

## 1. 一个项目包含什么

```text
项目
  ├── Schema：问题定义
  ├── 种子：真实样例
  ├── 样本：待审核或已审核的数据
  ├── 数据集快照：冻结后的训练数据
  └── 模型产物：训练结果
```

一个项目建议只对应一个领域。不要把完全不同的业务混在一起。

## 2. 创建项目

在首页点击“新建项目”，填写：

| 字段 | 说明 | 示例 |
|---|---|---|
| 名称 | 项目显示名 | 客服工单分流 |
| 领域 | 业务、输入和需要做的决策 | SaaS 客服工单，判断团队和紧急程度 |
| 语言 | 生成和评估语言 | 简体中文、English |

## 3. 设计 Schema

打开项目的 Schema 标签，添加至少一个问题。

### 3.1 Choice

用于多选一：

```json
{
  "key": "team",
  "type": "choice",
  "instructions": "这条工单应该由哪个团队处理？",
  "criteria": {
    "billing": "退款、发票、重复扣款、支付问题",
    "technical": "Bug、故障、API 报错、性能问题",
    "sales": "价格、试用、报价、合同"
  }
}
```

UI 中每个选项由“选项键名”和“说明”组成。

### 3.2 Noul

用于是/否概率：

```json
{
  "key": "urgent",
  "type": "noul",
  "instructions": "这条工单需要在今天处理吗？"
}
```

答案值是 0 到 1 的概率。大于等于 0.5 时导出为“是”。

### 3.3 Score

用于有序等级：

```json
{
  "key": "priority",
  "type": "score",
  "instructions": "这条工单的优先级是多少？",
  "criteria": ["可以等待", "本周处理", "今天处理"]
}
```

标签从低到高排列，导出的分数从 0 开始。

### 3.4 设计建议

- 键名使用英文小写，例如 `team`、`urgent`、`priority`。
- 选项互斥；如果确实需要多标签，请拆成多个 Noul 问题。
- 不要使用没有边界的“其他”选项。
- 问题说明描述“要判断什么”，选项说明描述“边界条件”。
- 一个项目中的问题尽量围绕同一个业务场景。

## 4. 种子与导入

### 4.1 手动添加种子

在“种子”标签点击“添加种子”。

状态 JSON：

```json
{
  "ticket": "我这个月被重复扣款了，请退还多收的费用。"
}
```

标签 JSON 可选：

```json
{
  "team": "billing"
}
```

保存后点击“送入审核”，种子会变成待审核样本。

### 4.2 下载模板

种子页和样本页都提供“下载模板”：

- JSONL 模板
- CSV 模板

CSV 列：

```text
state,labels,language
```

样本页额外支持 `difficulty` 和 `heldout`。

### 4.3 批量导入

规则：

- 单文件最大 20 MB，最多 5000 条；
- UTF-8 编码；
- `state` 可以是 JSON 对象或普通字符串；
- `labels` 中的问题键必须已经在 Schema 中存在；
- 导入后的数据仍是 `pending`，需要审核。

### 4.4 真实留出样本

建议准备一批来自真实业务的数据作为测试集。

创建手动样本时打开“真实留出样本”。这些样本会固定进入 test 划分，不参与训练。

建议：

- 正式评估准备 50–200 条；
- 小项目至少 20 条；
- 覆盖所有标签和主要边界情况；
- 不要用同一批留出数据反复调参。

## 5. 生成数据

打开“生成”标签。

| 字段 | 说明 |
|---|---|
| 样本数 | 单次最多 2000 |
| 语言 | 中文 / 英文 |
| Teacher | Jev、LLM 直接标注、不使用 Teacher |
| 简单 / 中等 / 困难 | 百分比，总和保持 100% |
| 困难/歧义比例 | 0–1 的提示比例 |
| 平衡标签 | 尽量让各标签覆盖均匀 |

### 5.1 Teacher 选择

**Jev Teacher**

- 使用 Jev 生成教师答案；
- 需要配置 Jev Key；
- 仍然需要人工审核。

**LLM 直接标注**

- 生成模型同时输出弱标签；
- 成本低，但质量取决于生成模型；
- 必须人工审核。

**不使用 Teacher**

- 只生成文本；
- 答案由人工填写。

### 5.2 高级设置

展开高级设置可以：

- 追加自定义 Prompt；
- 完全自定义 System Prompt 和 User Prompt 模板；
- 设置 Think 预算（`reasoning.max_tokens`）；
- 设置 Think 等级（`reasoning_effort`）；
- 设置温度；
- 预览完整 LLM 请求体。

“自定义 Prompt 模板”默认关闭，此时使用内置模板。打开后会显示带默认内容的 System 和 User 模板，可以在此基础上修改。自定义模板会完全替换默认内容，可使用 `{{x}}` 占位符插入当前项目、Schema、种子、难度和采样参数。常用占位符包括：`{{project_name}}`、`{{language}}`、`{{count}}`、`{{schema_json}}`、`{{seeds_json}}`、`{{default_system}}`、`{{default_user}}`、`{{custom_prompt}}`。完整的占位符列表会显示在高级设置中。

Think 预算和等级只对支持对应参数的 Provider 生效。留空时使用 Provider 默认值。

### 5.3 生成过程

生成任务会显示：

- 进度；
- 已生成、已接受、已拒绝数量；
- 当前阶段；
- 错误信息。

任务可以暂停、继续或取消。完成后样本仍需要审核。

### 5.4 质量建议

- 先用 50–200 条小批量试跑；
- 用 5–20 条真实种子锚定领域语言；
- 检查短文本、长文本、否定、含糊表达；
- 不要只依赖合成数据做最终评估。

## 6. 人工审核

打开“审核队列”。

### 6.1 队列

- 左侧显示待审核样本；
- 可以按项目筛选；
- 可以勾选多条批量接受或拒绝；
- 只显示 `pending` 样本。

### 6.2 修改答案

每个问题是一张答案卡：

- Choice：选择选项；
- Noul：输入 0–1 概率；
- Score：选择有序标签或输入分数；
- 可以填写审核备注；
- 点击“保存答案”。

### 6.3 接受与拒绝

接受前必须为每个问题提供答案。

- 接受：进入下一次数据集快照；
- 拒绝：不进入训练集；
- 重新运行 Jev：重新获取教师答案。

## 7. 冻结数据集

进入“数据集”标签，点击“冻结快照”。

### 7.1 包含条件

- 样本已接受；
- 每个问题都有答案；
- 数据可以导出。

如果有已接受样本缺少答案，冻结会失败，请回到审核页补全。

### 7.2 版本

每次冻结都会创建新版本。旧快照保持可用，不会影响已有训练任务。

### 7.3 划分

- 同一来源的样本不会被拆到训练集和测试集；
- 真实留出样本固定进入 test；
- 系统会尽量保证 train / validation / test 都存在；
- 数据太少时可能无法保证三部分都有。

### 7.4 下载格式

每个快照可以下载：

- **Canonical JSONL**：完整字段，适合审计和转换；
- **Laya JSONL**：用于 Laya 训练；
- **GLiNER JSONL**：用于 GLiNER 微调。

### 7.5 删除快照

快照卡片底部提供“删除”：

- 删除记录和对应导出文件；
- 存在运行中的训练或评估时不能删除；
- 已生成的模型产物会保留。

删除不可恢复，建议先下载 JSONL 或备份 `data/datasets/`。

## 8. 数据质量检查

冻结前建议检查：

- [ ] 每个标签都有足够样本；
- [ ] 长尾标签没有被忽略；
- [ ] 已抽查困难、否定、含糊和长文本；
- [ ] 没有明显重复；
- [ ] 教师和人工答案冲突较大的样本已复查；
- [ ] 真实留出样本已标记；
- [ ] 训练集和测试集没有同源泄漏；
- [ ] 标签分布符合业务预期。

## 9. 备份

建议备份：

- `backend/.env`
- `data/autolaya.db`
- `data/datasets/`
- `data/artifacts/`
- `models/`
